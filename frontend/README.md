# 🚦 TrafficIQ — Kolkata Frontend (Streamlit)

Dashboard for the Kolkata Traffic Congestion Prediction System.

```
TomTom API (traffic) ─┐
                      ├─> FastAPI backend ─> ML model ─> prediction response ─> this Streamlit dashboard
OpenWeather API ──────┘
```

The frontend **only shows data returned by the FastAPI backend**. There is no random, simulated or
hardcoded traffic / weather / ML data. If something is missing, the dashboard says **"Data unavailable"**.
No API keys live in this code — the frontend only knows the backend URL.

## Run

The backend must be running in a separate terminal first (default `http://127.0.0.1:8000`).
Quick check: open `http://127.0.0.1:8000/health` — but note a healthy `/health` does **not** prove
ML predictions work; the dashboard checks the prediction endpoint separately.

```bash
cd frontend
pip install -r requirements.txt
streamlit run app.py
```

Open `http://localhost:8501`.

## Configuration

Each setting is read from an **environment variable**, then **Streamlit secrets**
(`.streamlit/secrets.toml`, see `secrets.toml.example`), then a default.

| Setting | Default | Purpose |
|---|---|---|
| `BACKEND_URL` | `http://127.0.0.1:8000` | Backend base URL. **Set to the deployed URL in production.** |
| `REQUEST_TIMEOUT_SECONDS` | `10` | Timeout for each backend call. |
| `HISTORICAL_CSV_PATH` | `data/historical_traffic.csv` | CSV used for the speed-trend chart. |
| `SEND_LOCATION_TO_BACKEND` | `true` | `false` = send no location, so the backend uses its default Kolkata location. |

TomTom and OpenWeather keys belong in the **backend** `.env` / deployment secrets — never here, and
never committed. `.gitignore` already excludes `.env` and `.streamlit/secrets.toml`.

## Files

| File | Purpose |
|---|---|
| `app.py` | Streamlit UI: sidebar, KPI cards, 5 tabs. |
| `traffic_core.py` | No-Streamlit logic: API client with error handling, tolerant response parsing, traffic-status classification, CSV history loader. Kept separate so it can be unit-tested. |

## ⚠️ To confirm with the backend / ML teams

I could not see the real backend or the repo while building this, so these are assumptions. Each is
isolated in one place so it is quick to change. The **Pipeline → "Raw backend responses"** expander
shows the exact JSON the dashboard received — use it to verify.

1. **Response field names of `GET /api/v1/data/current`.** The parser looks for the usual names
   (`current_speed`/`currentSpeed`, `free_flow_speed`/`freeFlowSpeed`, `temperature`/`temp`, `humidity`,
   `condition`/`weather[0].description`, `rain`, `wind`, `collected_at`), flat or nested under
   `traffic` / `weather`. Anything not found shows "Data unavailable". Edit `parse_current()` in `traffic_core.py` if the real names differ.
2. **How to request a specific location.** The frontend sends `latitude` / `longitude` (query params on GET,
   plus `location` in the POST body). The guide only says `{}` selects the default location, so the real
   parameter names are unknown. If the backend ignores them the dashboard warns that all locations
   returned identical data. Edit `location_params()` / `location_payload()` in `app.py`,
   or set `SEND_LOCATION_TO_BACKEND=false`.
3. **Congestion thresholds** (`TRAFFIC_THRESHOLDS` in `traffic_core.py`): ratio of current to free-flow speed,
   Low ≥ 0.75, Moderate ≥ 0.50, otherwise High. **Provisional** — the guide asks to agree thresholds with the ML/backend teams.
4. **Model output categories and name.** The prediction text is displayed as returned; confidence ≤ 1 is
   shown as a percentage. The old "XGBoost + LSTM" label was removed because `predictor.py` imports a random-forest module — confirm the real model name.
5. **Temperature unit.** Shown as °C, so the backend must request OpenWeather `units=metric`.
6. **Kolkata coordinates** are approximate landmark positions. Verify them, and test that TomTom actually
   returns flow data for each point — a valid coordinate does not guarantee that. A location with no data shows "Data unavailable".
7. **Historical CSV format.** Columns are detected by name (time: `collected_at`/`timestamp`/…, speed:
   `current_speed`/`speed`/…, optional `location`, optional `free_flow_speed`). If there is no CSV or no rows for
   the location, the chart is replaced by "Historical data is not yet available for this location."

## Not done yet (by design, per the guide)

- Real routes / ETAs — needs the TomTom Routing API.
- ML performance metrics — shown only once the ML team provides verified numbers.
- More than 5 locations, forecast horizons, advanced charts.

## Testing

**Verified in development** (against a local stand-in for the backend, not the real one, and a recording
stand-in for Streamlit): parsing of nested and flat responses, status classification, every error path
(backend down, timeout, 401, 404, 422, 429, invalid JSON, wrong schema, model failure, `prediction: null`),
no crash in any of them, CSV loading with missing/odd files, and a source scan confirming no `random`, no
hardcoded sensor/accuracy numbers, no Delhi data and no API keys.
